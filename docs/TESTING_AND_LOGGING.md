# Система тестирования и логирования Auto Arsenal

## Обзор

В проект добавлены две важные системы для контроля качества и отладки:
1. **Система логирования** — автоматическая запись событий игры в файлы
2. **Система тестирования** — автоматические тесты для проверки корректности кода

## Система логирования

### Описание

Система логирования записывает все важные события игры в файлы с временными метками. Это помогает:
- Отлаживать ошибки и баги
- Отслеживать производительность
- Анализировать игровые события
- Понимать последовательность действий перед ошибкой

### Расположение файлов

- **Код логгера:** `src/logger.py`
- **Файлы логов:** `logs/game_ГГГГММДД_ЧЧММСС.log`

### Уровни логирования

1. **DEBUG** — детальная отладочная информация (только в файл)
2. **INFO** — важные события игры (файл + консоль)
3. **WARNING** — предупреждения о потенциальных проблемах
4. **ERROR** — ошибки, которые не приводят к краху
5. **CRITICAL** — критические ошибки, возможно падение

### Использование в коде

```python
from src.logger import get_logger

logger = get_logger()

# Простые сообщения
logger.info("Игра запущена")
logger.debug("Позиция игрока: (100, 200)")
logger.warning("Низкий FPS: 30")
logger.error("Не удалось загрузить текстуру")

# Игровые события с данными
logger.game_event("player_levelup", level=5, xp=250)
logger.game_event("wave_complete", wave=3, kills=42)

# Метрики производительности
logger.performance("fps", 60)
logger.performance("enemy_count", 15)
```

### Формат записи в логе

```
2026-07-09 15:30:45 [INFO] AutoArsenal: Начало новой игры - сброс состояния
2026-07-09 15:30:45 [DEBUG] AutoArsenal: Игрок создан на позиции (1500, 1700)
2026-07-09 15:30:50 [INFO] AutoArsenal: [GAME_EVENT] player_levelup: level=2, xp=5
2026-07-09 15:31:15 [WARNING] AutoArsenal: Низкая производительность: 45 FPS
```

### Особенности

- **Автоматическое создание папки** `logs/` при первом запуске
- **Singleton-паттерн** — один экземпляр логгера на всю игру
- **Ротация файлов** — новый файл при каждом запуске
- **UTF-8 кодировка** — поддержка русских символов
- **Thread-safe** — безопасен для многопоточности

- Убедиться, что изменения не сломали существующий код
- Документировать ожидаемое поведение
- Быстрее разрабатывать с уверенностью

### Добавление новых тестов

1. Создайте файл `tests/test_<название>.py`
2. Импортируйте unittest и тестируемые модули
3. Создайте класс-наследник `unittest.TestCase`
4. Напишите методы тестов (имя с префиксом `test_`)

**Пример:**
```python
import unittest
from src import settings

class TestNewFeature(unittest.TestCase):
    def test_something_works(self):
        result = 2 + 2
        self.assertEqual(result, 4, "Математика должна работать")
    
    def test_value_positive(self):
        self.assertGreater(settings.SOME_VALUE, 0, 
                          "Значение должно быть положительным")

if __name__ == '__main__':
    unittest.main()
```

## Интеграция в рабочий процесс

### При разработке

1. **Перед началом работы:** запустите тесты, убедитесь что всё работает
2. **Во время работы:** добавляйте логирование в новый код
3. **После изменений:** запустите тесты снова
4. **При багах:** проверьте логи для понимания проблемы

### При отладке

1. Запустите игру с включенным логированием
2. Воспроизведите баг
3. Откройте последний файл в `logs/`
4. Найдите последовательность событий перед ошибкой
5. Исправьте код
6. Запустите тесты для проверки

### Continuous Integration (будущее)

Тесты готовы для интеграции в CI/CD:
```yaml
# Пример для GitHub Actions
- name: Run tests
  run: python3 tests/run_tests.py
```

## Заключение

Системы тестирования и логирования делают разработку:
- **Безопаснее** — баги находятся автоматически
- **Быстрее** — не нужно вручную проверять каждую функцию
- **Надёжнее** — логи помогают понять проблемы пользователей
- **Профессиональнее** — следование индустриальным стандартам
